# 문제 후보 평가 기준표 및 채점

> 채점 주체: 총감독(메인 세션) 단일 주체 — 기준 일관성 확보
> 입력: 기업별 1차 리서치(`<기업>/research.md`, 기업당 후보 3개, 공개 출처 교차확인 완료)
> 사용자 지시 반영: "해결책 스코프가 예선 수준에 맞게 충분히 커야 함" → 스코프 기준 신설(20%) 및 **후보 병합(스위트) 전략** 도입

## 평가 기준 (가중치)

| 기준 | 가중치 | 정의 |
|---|---|---|
| 솔루션 스코프·확장성 | 20% | end-to-end 제품형 해법인가(탐지→리포트→수정제안→CI), 인접 문제 확장 여지 |
| 문제 실재성·근거 강도 | 20% | 접근 가능한 공개 출처의 수·질 (실격 방지 직결) |
| Codex 플러그인 적합성 | 15% | 개발자 워크플로 도구로 자연스러운가 |
| 구현 비용(시간) | 15% | 마감 내 "실행되는 데모" 가능성 (비용 낮을수록 고득점) |
| AI 검증 가능성 | 10% | 심사 AI가 출처 URL을 열람·확인 가능한가 |
| 데모 재현성 | 10% | 심사자가 API 키 없이 로컬 재현 가능한가 |
| 기업 관심사 정합성 | 10% | 각사 공개 인터뷰 방향과의 일치 |

채점: 기준별 0~10점 → 가중 합산(만점 10).

| 기업 | 확정 플러그인 | 구성 스킬 | 예상 비용 |

공통 아키텍처: `references/*.json`(법령·기준 룰 데이터, 조문 역추적 가능) + `scripts/*.py`(python3 표준 라이브러리만, 결정론) + `samples/`(정상·위반 혼합) + PASS/FAIL 리포트 + non-zero exit(CI 게이트) + SKILL.md(스킬별).

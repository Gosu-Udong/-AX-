# pii-guard — 개인정보(PII) 평문 노출 정적 검사

## 언제 쓰나 (사용 시나리오)
- 커밋/릴리스 전, 코드·로그·설정에 **주민등록번호·카드·계좌·전화·이메일**이 평문으로 남았는지 자동 점검할 때.
- PII가 **로그로 출력**되거나 **네트워크로 전송**되는지, 특히 **제3자·국외 호스트**(예: alipay/overseas)로 실려 나가는지 확인할 때. (카카오페이 4,045만명 개인정보 국외이전 제재 유형)
- 보안/컴플라이언스팀이 코드 레벨을 일일이 심사하기 전 **1차 자동 스캔**으로 쓸 때.

## 무엇을 검사하나
1. **PII 패턴 검출**: 주민등록번호, 카드번호(**Luhn 검증**으로 오탐 제거), 계좌번호(자릿수 하한으로 날짜 오탐 제거), 휴대전화번호, 이메일.
2. **마스킹 판정**: 이미 마스킹된 값(`900101-*******` 등)은 위반이 아니라 "마스킹 처리"로 별도 집계 → 평문만 위반으로 카운트.
3. **노출 컨텍스트 승급**: 같은 라인에 로그/네트워크 sink가 있으면 `high`, 제3자·국외 호스트 상수가 결합되면 `critical`로 심각도 상향.

## 실행 명령
```bash
# 코드/로그 디렉토리 스캔 (사람이 읽는 리포트)
python3 scripts/pii_guard.py samples/pii

# JSON 출력
python3 scripts/pii_guard.py samples/pii --json

# 추가 확장자 지정
python3 scripts/pii_guard.py samples/pii --ext .tsx
```

## 입력 형식
- 대상 확장자(기본): `.py .js .ts .java .go .rb .php .kt .log .txt .json .env .yml .yaml .properties .sql .csv .xml .ini .conf` (`--ext`로 추가).
- 파일/디렉토리 모두 지정 가능. 결과는 파일:라인 단위.

## 출력 해석
- `FAIL L<라인> [심각도] <유형> = <마스킹된 값> (<컨텍스트>)`. **원문 PII는 출력하지 않고 마스킹**하여 표기한다.
- 심각도: `MEDIUM`(평문 저장) < `HIGH`(로그/네트워크 노출) < `CRITICAL`(제3자·국외 전송 소지).
- PII 노출이 1건이라도 있으면 **exit code 1**, 없으면 exit 0. 요약에 마스킹 처리 건수도 표기.

## 근거 데이터 / references
- 패턴·조문·출처·sink·제3자 호스트 목록: `references/pii_rules.json`.
- 핵심 근거: 개인정보 보호법·신용정보법(고유식별정보 암호화·마스킹·국외이전 동의 의무), 금융분야 가명·익명처리 안내서.

## 주의
- 샘플의 모든 PII는 **가상 테스트값**이며 실제 개인정보가 아니다. 실환경 스캔 시 결과 리포트에 실제 값이 남지 않도록 마스킹 출력을 유지한다.
